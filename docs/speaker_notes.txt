Slide 1 — Title Slide                                          [~20 sec]
------------------------------------------------------------------------

Good morning everyone. Welcome to our FSE 570 capstone presentation.
Today we are presenting the Autonomous OSINT Investigation Swarm — a
multi-agent AI system that turns a plain-English question into a fully
cited, audit-ready financial misconduct investigation in under three
seconds.

------------------------------------------------------------------------
Slide 2 — The Problem                                          [~40 sec]
------------------------------------------------------------------------

Let's start with the problem this system solves. A compliance analyst
investigating whether a public company is tied to money laundering has
to manually open five different sources — SEC filings, the OFAC
sanctions list, court dockets, news archives — read through hundreds of
documents, cross-reference everything, and write a summary report. That
process takes about two and a half hours per investigation.

Our system performs the same coverage in 2.7 seconds — a 3,100-times
speedup. That is not an approximation; every step was benchmarked
against a manual analyst baseline.

------------------------------------------------------------------------
Slide 3 — What It Delivers                                     [~30 sec]
------------------------------------------------------------------------

In concrete numbers: one plain-English query pulls from four public data
sources — SEC, OFAC, CourtListener, and GDELT news. For Tesla, that
produces 1,125 individual evidence rows, 98 percent of which carry a
direct citation link you can click and verify. The entire pipeline runs
cache-first — no API calls at runtime — so every investigation replays
instantly from disk.

ARNAB MITRA — Slides 4, 5, 6

------------------------------------------------------------------------
Slide 4 — System Architecture                                  [~35 sec]
------------------------------------------------------------------------

The system runs in seven-and-a-half layers. At the base is the core
library — raw connectors to each data source. Above that, the MCP layer
handles caching and confidence processing. The Lead Agent resolves the
entity and uses an LLM to plan tasks. Three specialist agents then
execute those tasks in parallel. The Reflexion Layer cross-checks
findings and surfaces gaps. The Output Layer assembles the final report
and audit trail. And at the top, Llama 3.1 writes the structured analyst
narrative.

------------------------------------------------------------------------
Slide 5 — Architecture Diagram                                 [~25 sec]
------------------------------------------------------------------------

Here is that flow visually. A query enters the Lead Agent, which
resolves the entity and builds a task queue. The three specialists —
Corporate, Legal, and Social Graph — each hit different data sources in
parallel. Their findings pool into the evidence store, pass through
Reflexion and the Knowledge Graph, then into the Output Layer. The LLM
writes the final narrative only after all evidence is locked in.

------------------------------------------------------------------------
Slide 6 — LLM Integration                                      [~30 sec]
------------------------------------------------------------------------

One model — Llama 3.1-8b-instant via Groq — powers five distinct
policies. The Planner decomposes the query into three to five bounded
subtasks. The Action Policy tells each specialist agent which tool to
call next. The Stop Policy decides when enough evidence has been
gathered. The Reflexion Ranker prioritizes follow-up actions after
detecting gaps or conflicts. And the Final Narrative produces the
structured analyst report. Every LLM call uses strict JSON mode with
retry-with-repair — if the model returns malformed output, it is
corrected and retried rather than failing silently.

RAJ KUMAR MAHTO — Slides 7, 8, 9
================================================================

------------------------------------------------------------------------
Slide 7 — Data Sources                                         [~30 sec]
------------------------------------------------------------------------

The system pulls from four fully public sources. SEC EDGAR provides up
to 500 filings per entity — 10-Ks, 8-Ks, Form 4s, proxy statements.
The OFAC SDN list covers over 18,000 sanctioned entities and requires no
API key. CourtListener provides up to 20 federal court dockets per
query. GDELT delivers up to 100 English-language adverse media articles.
All data is cached after the first pull — investigations at runtime make
zero network calls.

------------------------------------------------------------------------
Slide 8 — Specialist Agents                                    [~30 sec]
------------------------------------------------------------------------

The three specialist agents each own a slice of those sources. The
Corporate Agent handles SEC filings and assigns confidence by form type
— an 8-K scores 0.95, a Form 4 scores 0.75. The Legal Agent
fuzzy-matches against the OFAC SDN list and queries CourtListener for
federal dockets. The Social Graph Agent pulls GDELT articles, filters
for English, and scores each by relevance — whether the title includes
both the entity name and a risk keyword. All three share the same
interface: receive a task, return a list of Evidence objects.

------------------------------------------------------------------------
Slide 9 — Runtime Pipeline                                     [~30 sec]
------------------------------------------------------------------------

The full pipeline runs in five steps. Entity resolution takes 0.1
seconds — "Tesla" maps to CIK 0001318605. LLM planning takes 0.2
seconds. The three agents gather 1,125 evidence rows in 1.2 seconds —
the bulk of the work. Reflexion and LLM ranking take 0.6 seconds,
surfacing 88 cross-check conflicts. Output generation and the analyst
narrative take the final 0.6 seconds. Total: 2.7 seconds, with an
overall confidence score of 0.81.

ADITYA POKHARNA — Slides 11, 12, 13, 14, 15

------------------------------------------------------------------------
Slide 11 — Evaluation: Per-Entity Metrics                      [~25 sec]
------------------------------------------------------------------------

Across all five entities — Tesla, Ford, Boeing, Alphabet, and JPMorgan
— the system averages 1,010 findings per investigation, 2.67 seconds
end-to-end, a 97.7 percent citation rate, and full four-of-four source
coverage every time. Tesla leads at 1,125 findings. Ford comes in lower
at 598, largely because GDELT news coverage for automotive companies is
sparser than for tech and finance. Every entity achieves full source
coverage — no investigation returns a partial result.

------------------------------------------------------------------------
Slide 12 — Speedup, Confidence & Test Coverage                 [~25 sec]
------------------------------------------------------------------------

The 3,100-times speedup breaks down by task. SEC review alone is 1,800
times faster. Adverse media scanning is 2,700 times faster. Confidence
scoring is tiered by source reliability — an SEC 8-K starts at 0.95,
OFAC at 0.90, CourtListener at 0.85, and low-relevance GDELT articles
at 0.30. The system is backed by 219 unit tests spanning all eight
layers, from raw connectors through to the LLM narrative module.

------------------------------------------------------------------------
Slide 13 — Evaluation Framework                                [~20 sec]
------------------------------------------------------------------------

Five formal evaluation criteria were applied. Correctness and depth:
97 to 98 percent citation rate, 598 to 1,125 findings per entity.
Cross-agent verification: Reflexion runs on all three specialist agents.
System generality: five entities across three industries, with automatic
resolution for any publicly traded US company. Code quality: 219 tests
and a full deployment runbook. Speed: 3,100 times faster than manual.
All five criteria are met.

------------------------------------------------------------------------
Slide 13 — Design Decisions                                    [~30 sec]
------------------------------------------------------------------------

Six decisions shaped the architecture. LLM drives orchestration, but
evidence stays source-grounded — that is how the system reaches 97 to
98 percent citation rather than generating findings from the model's
own memory. Everything runs cache-first, so there are zero runtime API
dependencies. Entity and Evidence objects are frozen dataclasses —
agents cannot mutate each other's findings. Missing data is explicit: a
confidence of zero and a cache_missing flag mean gaps surface in the UI
rather than disappearing silently. Every LLM call validates against a
JSON schema with retry-on-failure. And the system deploys to Render.com
with no external dependencies at runtime.


------------------------------------------------------------------------
Slide 14 — Limitations / Future Work                           [~30 sec]
------------------------------------------------------------------------

No system is finished — and acknowledging that matters. Three current
limitations: first, the data is only as fresh as the last pull — OFAC,
court records, and GDELT go stale without a manual refresh. Second, the
GDELT signal is English-only, so adverse media in other languages is
missed entirely. Third, the LLM narrative is contract-bound but not
sentence-level verified against individual evidence rows.

On the future work side: the most impactful next step is automated
nightly data refresh, removing the manual pull requirement. After that,
removing the five-entity cache ceiling so any public company resolves at
query time. And longer term, integrating licensed sources like
OpenCorporates or Dun & Bradstreet to cover private and international
entities.

------------------------------------------------------------------------
Slide 15 — Conclusion                                          [~25 sec]
------------------------------------------------------------------------

Three things to take away from today. What we built: a seven-layer,
multi-agent system that converts a plain-English query into a fully
cited financial misconduct report, pulling from four public sources in
under three seconds. What we proved: a 3,100-times speedup over manual
analysis, a 97.7 percent citation rate, full source coverage on every
entity tested, and 219 unit tests validating every layer. And what is
next: automated data refresh, on-demand coverage for any public company,
and integration of private and international sources to push the system
beyond its current boundaries.
